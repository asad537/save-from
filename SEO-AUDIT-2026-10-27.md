# Save-Froms Live SEO Audit — 2026-10-27

Scope: all 77 URLs in https://save-froms.net/sitemap.xml were fetched and parsed (title, meta, canonical, headings, word count, images, links, JSON-LD, hreflang, timing). Server was not accessed (key-based SSH is not enabled; password login was not used). Everything below is from the public site plus this repo.

## What is already fine

- HTTP, www and trailing-slash variants all 301 to `https://save-froms.net/...`. UTM query strings keep the clean canonical.
- robots.txt and sitemap are live, 77 URLs, all return 200. No orphan pages, no broken internal links.
- Every page has one H1, a unique title, a unique meta description, a self canonical, `index,follow`, valid JSON-LD (WebApplication / Organization / WebSite / WebPage, BlogPosting + BreadcrumbList on posts).
- All images have alt, title, width and height. Static assets are cached 7 days and served with Brotli.
- No exact-duplicate pages. Max body overlap between any two pages is 31.5% (see below).

### 3. Over-optimized, unnatural templated copy

- The word "public" is in 37 of 77 titles, 28 H1s and 62 of 77 meta descriptions. The same hedging sentence ("One complete public URL; the result lists only the formats this source really offers") sits on every tool page. This reads as a template to Google and to users.
- H1s do not match how people search. Examples: "YouTube Short Download Tool" (search: *YouTube Shorts downloader*), "Instagram Video Download Tool" (*Instagram video downloader*), "Check Public Instagram Stories", "Download Available TikTok MP3 Audio", "Public TikTok MP4 Downloader", "Use a YouTube Link Downloader". Drop "Public", "Tool", "Available", "Check", "Use a" from H1s and use the exact keyword plus one benefit.
- Body copy is defensive and legalistic (permitted / authorized / cannot bypass / responsible use) and light on actual help. Users searching these terms want steps, screenshots and format answers; the legal note can be one line linking to Terms.
- `/supported-sites` has 5.1% "download" keyword density and a 79-character title.

### 4. Language and international signals are wrong

- `/blog/baixar-video-instagram-links-publicos-guia` is Portuguese but the page declares `lang="en"` and `og:locale="en_US"`.
- The four Arabic posts use `og:locale="ar_AR"`, which is not a valid locale (use `ar_SA`, `ar_EG` or just `ar`).
- There is no hreflang anywhere, no Arabic or Portuguese hub or category, and the navigation stays English on those pages. Arabic posts of 510–575 words targeting head terms like "تحميل فيديو يوتيوب" will not rank. Either build an `/ar/` section (home + tool pages + posts, hreflang pairs) or stop adding Arabic posts until that exists.

### 5. Trust and E-E-A-T gaps

- Author everywhere is an Organization ("Save-Froms Editorial Team"). No named person, no operator identity on About (`OPERATOR_NAME` still blank).
- Only 2 outbound links across all 77 pages. No sources or citations in guides.
- Homepage still shows a fabricated "Example result" block (`https://www.youtube.com/watch?v=abc123`, "12:34", a list of qualities). Replace it with a real screenshot of a real result or remove it.
- Several blog covers are 1.5 KB generic SVG placeholders (e.g. `tiktok-mp4-quality-guide.svg`, `youtube-1080p-format-guide.svg`) and the same JPG is used as cover for two different Vimeo posts. No screenshots exist anywhere on the site.
- All 68 posts are dated 2026-10-06 to 2026-10-26. Publishing 68 posts in three weeks on a new domain with templated copy is a pattern Google's scaled-content policy targets. Slow down and deepen instead.

## Technical issues

| Issue | Detail | Fix |
|---|---|---|
| `/index.php` duplicate homepage | Returns 200 with canonical `https://save-froms.net/index.php`. | 301 `/index.php` → `/` (web server rule or Laravel middleware). |
| Blog pagination | `/blog?page=2..4` all canonical to `/blog`, identical titles. `/blog?page=5` is empty but returns 200. 36 of 68 posts are only listed on pages 2–4, so they get almost no listing-page equity. | Self-canonical per page, title "… – Page 2", 404 for out-of-range pages, show more posts per page or add category pages (YouTube, Instagram, TikTok, Facebook…). |
| Server response time | TTFB 0.8–1.6 s on every page (Hostinger shared, `x-hcdn-cache-status: DYNAMIC`, `Cache-Control: no-cache, private`). | Enable full-page caching for anonymous GETs (Hostinger/LiteSpeed cache or `spatie/laravel-responsecache`), and stop setting a session cookie on public pages so the CDN can cache HTML. |

## Recommended order of work

1. Consolidate: 301 the three duplicate tool pages and the six 2026-10-06 short posts into their stronger siblings. Fix `/index.php`.
2. Rewrite every tool-page H1 and title to the exact natural keyword; remove the shared boilerplate sentence; cut "public" from titles and descriptions where it is not the point.
3. Expand the nine thin tool pages with real screenshots and device-specific steps. Add a real screenshot to the homepage in place of the fake example result.
4. Fix language attributes and `og:locale`; decide on an `/ar/` section or pause Arabic.
5. Enable full-page caching and self-host fonts; add security headers.
6. Add a named author with a bio, operator identity on About, and cite platform help pages in each guide.
7. Blog: self-canonical pagination, category pages per platform, no more than one new post per topic cluster.

Not verified here: Search Console coverage, backlinks, Core Web Vitals field data and the production mailbox addresses. Those need Search Console access.
